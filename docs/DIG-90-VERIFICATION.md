Viewport sweep (320/344/360/375/414/768/1024/1280): clean everywhere except
at exactly 320 px, where 48 px display headings bleed 3–7 px
(`/services/` "development."/"management.", `/faq/` "something?",
legacy blog button 4 px). 344 px (Galaxy Fold) and up are clean. Fixing it
means changing the brand display size or allowing mid-word breaks in
headings — a design-token decision, recorded here instead of made
unilaterally.

Safari/WebKit cannot run on this Linux host, so the Safari position comes
from a feature audit of the built CSS/HTML: all 10 media queries use range
syntax (`width>=768px`), which sets the hard floor at **Chrome 104+,
Firefox 102+, Safari 16.4+**. `dialog`/`showModal`/`::backdrop`, `:has()`,
`:focus-visible`, and `@layer` all land at Safari 15.4+, and no `oklch()`
ships; `color-mix()` is behind an `@supports` guard. The font fallback
faces need Safari 17+ and fail gracefully to the previous behaviour
below that. Content stays readable below the floor (mobile-first base
styles, system fonts); the modal and responsive layout degrade. A real
WebKit pass (Safari 16.4/17, one iOS device) is still worth doing before
go-live — DIG-91 owns the go-live checklist and can carry it.
